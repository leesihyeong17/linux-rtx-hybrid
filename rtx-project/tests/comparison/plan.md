# 측정 전 고정한 조건

주 비교는 V3(RB+CACHE+TAIL)와 V4(HYBRID K=16+CACHE+TAIL)의 clean bulk에서 게스트 전체 busy ns/수신 byte의 변화다. 같은 조건의 goodput과 RR p99를 함께 본다. 10개 독립 부팅 쌍의 변화율 중앙값과 쌍 단위 bootstrap 95% 구간(10,000회, seed 16)을 보고한다. 기준선 값이 0인 CPU 측정은 분모로 쓰지 않는다. 팀 계약의 3% CPU 개선·2% goodput 저하·5% p99 증가 기준은 제안값으로 표시한다. 구간이 0을 넘나들면 방향을 확정하지 않는다. 외부 팀 VM으로의 일반화나 K의 최적성은 이 시험 범위 밖이다.

원본 RB(V0), API 전환 RB(V1), 같은 통합 소스의 RB 기본·CACHE 단독, V4 K=4는 각 5개 독립 부팅으로 보조 비교한다. V3/V4의 STATS+ACK 시점 LIST 길이 계측도 각 5개 독립 부팅으로 실행한다. 계측 비용에는 두 계측이 함께 포함된다. 성능과 계측 결과를 합산하지 않는다. 같은 반복의 대응 구성을 번갈아 실행하고, 쌍의 순서는 seed 16으로 섞는다.

실제 TCP는 사설 veth와 두 네트워크 namespace, MTU 1500, 게스트 1 vCPU/768 MiB에서 수행한다. clean, 양방향 egress 0.5% 손실+4 ms 추가 RTT+송신 측 10% 재정렬, 같은 조건에서 SACK off를 사용한다. 각 조건에서 0.25초 워밍업과 1초 bulk 및 64 B RR를 실행한다. 수신 완료 바이트, 응답 일치, CPU tick, 송신 메모리 표본과 지연 원시값은 D의 endpoint/runner가 기록한다. 짧은 시험이므로 CPU tick 해상도와 무작위 손실의 변동을 함께 보고한다. 외부 NIC를 연결하지 않는다.

마이크로벤치마크는 같은 컴파일러와 공통 Kconfig에서 별도 부팅한다. 기존 append/split fixture는 워밍업 100 ms/조건 뒤 32회이며 public API 시간과 타이머 비용을 원본에 보존한다. N=4/64에서 적중 검색 4096회와 가장 오래된 노드부터의 unlink 묶음을 검사한다. 첫 묶음은 워밍업으로 제외하고 남은 32개의 부팅 내 중앙값을 사용한다. 부팅이 통계 단위다. 검색은 인덱스 생성·포인터 대조를 포함하고 unlink는 큐 크기가 N에서 0으로 줄어드는 동안의 구조 제거 시간이다. CPU 사이클은 추정하지 않는다.

첫 V4 계측에서 기본 전송의 ACK가 대부분 짧은 큐를 관찰했으므로 긴 큐를 만드는 보조 조건을 추가했다. 원래 75회 계획은 그대로 유지한다. 보조 시험은 손실·재정렬 없이 양방향 20 ms씩 지연, veth TSO/GSO/GRO off, netem limit 10000, 워밍업 1초 및 본 전송 2초로 고정한다. V3/V4 성능·계측 각 5회에서 ACK 시점 N>64 비중과 승격 횟수를 확인한다. 이 보조 결과는 clean 주 지표의 판정에 섞지 않는다.

첫 연산 실행에서는 짧은 append의 절반 이상이 단일 시계 눈금 안에 끝난 조건이 있었다. 보조 측정은 미리 할당한 skb 12개를 N=0부터 또는 32개를 N=64부터 연속 삽입한다. 할당과 송신 회계는 시간 경계 밖에서 수행하고, 이후 전체 큐를 검증한다. V3/V4 각 5회 부팅하고 부팅마다 초기 1묶음을 버린 뒤 32묶음의 중앙값을 기록한다. 이는 같은 N에서 독립 연산을 반복한 값과 구분한다.
